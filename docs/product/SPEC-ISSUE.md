## Problem Statement

拥有 Markdown、PDF、课程资料和个人笔记的个体自学者，通常需要在文件管理器、笔记软件、聊天机器人和题库之间来回切换。通用聊天机器人虽然能够解释概念，却难以证明回答来自哪些资料，也无法把“没理解的内容”稳定转化为练习和后续复习。

用户希望继续使用本地文件和现有编辑器，同时获得一个围绕当前资料位置工作的 AI 私教：回答可追溯、资料不足会明确说明、练习能够暴露知识缺口、复习记录可以长期保留。用户还希望资料、索引、会话和学习记录默认保存在本机，而不是绑定到托管账号或云端工作区。

## Solution

StudyNotes 是一个本地优先、资料有据的个人 AI 私教。用户注册一个或多个本地 Notebook workspace，直接读取其中的 Markdown、纯文本和带文本层 PDF。产品提供 BlockNote 风格 Markdown 编辑、PDF 阅读、选区提问、带 Source citation 的 AI 辅导、单选题与短答题练习、Gap record 和简单间隔复习。

Markdown 是笔记本主数据，BlockNote 元数据保存在同名 sidecar。模型通过用户配置的 OpenAI-compatible 服务联网调用；笔记图片上传到公开读七牛桶；其余资料、索引、会话和学习记录保存在本地。首版不提供通用空白聊天、隐藏记忆、多人协作、云同步或 DeepTutor 的完整模块生态。

## User Stories

1. 作为一个拥有多门课程资料的自学者，我希望注册多个 Notebook workspace，以便按课程或项目隔离资料。
2. 作为用户，我希望同一时间只激活一个 Notebook workspace，以便索引、会话和复习上下文不会混淆。
3. 作为使用 Finder、Obsidian 或 Git 的用户，我希望本地目录直接成为章节、Markdown 文件直接成为页面，以便产品内外的结构保持一致。
4. 作为用户，我希望新增、修改、移动或删除文件后资料树和索引自动更新，以便继续使用原来的文件工作流。
5. 作为用户，我希望目录移动或改名后系统提供重新定位入口，以便不丢失已有会话和复习记录。
6. 作为用户，我希望打开 Markdown 后获得 BlockNote 风格的块编辑体验，以便写作比纯文本更直观。
7. 作为用户，我希望每次保存后文件仍是普通 Markdown，以便其他编辑器和 Git 可以读取。
8. 作为用户，我希望块 ID、自定义属性和布局保存在同名 sidecar，以便 BlockNote 能恢复结构。
9. 作为用户，我希望外部编辑器修改文件时产品自动刷新，以便两个工具可以协作。
10. 作为用户，我希望应用内存在未保存内容时看到冲突提示而不是被静默覆盖，以便保护我的笔记。
11. 作为用户，我希望异常退出后可以恢复未保存草稿，以便减少写作损失。
12. 作为用户，我希望在界面内创建、重命名、移动和删除页面，以便直接管理文件系统。
13. 作为用户，我希望读取 YAML frontmatter 和正文中的标签，以便复用已有 Markdown 标签。
14. 作为用户，我希望使用 `.templates/` 中的模板创建页面，以便保持笔记结构一致。
15. 作为用户，我希望每日笔记保存为 `Daily/YYYY-MM-DD.md`，以便每日笔记仍然属于普通 Markdown。
16. 作为 Obsidian 用户，我希望产品读取 `[[Wiki Link]]` 和标准相对链接，以便已有链接继续工作。
17. 作为用户，我希望新建页面链接时使用标准 Markdown 相对路径，以便在普通 Markdown 工具中兼容。
18. 作为用户，我希望看到指向当前页面的反向链接，以便发现知识之间的关联。
19. 作为用户，我希望粘贴或拖入图片后立即上传七牛并插入普通 HTTPS 图片链接，以便外部编辑器也能显示图片。
20. 作为用户，我希望已有本地相对图片保持原样，直到我明确执行迁移，以便升级过程不破坏旧笔记。
21. 作为用户，我希望从当前段落、Markdown 块或 PDF 选区直接发起提问，以便围绕正在阅读的内容学习。
22. 作为用户，我希望每个 Learning session 至少绑定一个 Learning source，以便不存在脱离资料的通用聊天。
23. 作为用户，我希望在会话中显式固定其他 Markdown 页面、PDF 或片段，以便比较多个来源。
24. 作为用户，我希望 AI 默认采用引导式追问，同时可以显式要求直接解释，以便兼顾思考与效率。
25. 作为用户，我希望关键结论包含可点击的 Source citation 和原文片段，以便验证 AI 是否看对资料。
26. 作为用户，我希望资料不足时 AI 明确说明证据缺口，以便不被伪装成有据结论的回答误导。
27. 作为用户，我希望只有明确请求后才看到模型常识补充，并且它与有据内容明显区分，以便知道哪些内容不来自资料。
28. 作为用户，我希望通过上下文抽屉查看本次选中的资料、检索片段和实际发送范围，以便审计模型收到的内容。
29. 作为用户，我希望每个 Markdown 块和 PDF 选区可以拥有独立讨论线程，以便围绕局部内容持续追问。
30. 作为用户，我希望搜索、重命名、归档和删除 Learning session，以便管理会话历史。
31. 作为用户，我希望删除会话不会删除源文件、知识缺口或复习记录，以便安全清理聊天。
32. 作为用户，我希望使用 `Cmd+K` 同时搜索页面、正文、标签、会话、知识缺口和练习，以便快速回到相关学习内容。
33. 作为用户，我希望搜索结果能打开文件并定位到标题、块或 PDF 页码，以便不必手动寻找。
34. 作为用户，我希望未配置 embedding 时仍可使用本地全文检索，以便模型配置完成后立即可用。
35. 作为用户，我希望配置 embedding 后获得语义检索增强，以便更准确地找到表述不同但含义相关的内容。
36. 作为用户，我希望索引、向量和缓存都保存在本地，以便资料检索不依赖云端向量库。
37. 作为用户，我希望在阅读或对话结束后主动点击“考考我”，并收到生成练习建议，以便不在阅读过程中被自动弹题打断。
38. 作为用户，我希望完成单选题并看到正确答案、解释和资料引用，以便核对基础理解。
39. 作为用户，我希望短答题显示参考要点、评分依据、已命中项和遗漏项，以便理解自己为什么遗漏。
40. 作为用户，我希望可以修正 AI 自评结果，以便最终掌握状态由我负责。
41. 作为用户，我希望把未掌握内容保存为带资料证据的 Gap record，以便形成可见的学习缺口。
42. 作为用户，我希望 Review 页面按到期顺序展示复习项，以便每天知道该复习什么。
43. 作为用户，我希望复习后选择“重来”或“通过”，以便用简单操作更新 1、3、7、14 天间隔。
44. 作为用户，我希望可以修改或清除下一次复习时间，以便手动纠正调度。
45. 作为用户，我希望配置 OpenAI-compatible Base URL、API Key 和聊天模型，以便使用自己的模型服务。
46. 作为用户，我希望七牛配置是可选的，以便没有图片桶时仍能使用阅读、编辑、辅导、练习和复习。
47. 作为用户，我希望模型与七牛密钥保存在系统 Keychain，以便密钥不会进入浏览器、日志或 Markdown。
48. 作为用户，我希望首次使用联网模型或上传图片前明确看到数据边界，以便知道什么内容会离开本机。
49. 作为用户，我希望从笔记中移除图片时可以选择是否删除七牛对象，以便避免误删仍被其他资料引用的图片。
50. 作为用户，我希望删除页面时不会自动删除全部云端图片，以便避免不可恢复的数据损失。
51. 作为用户，我希望产品使用可见的学习记录做个性化，而不建立隐藏的长期记忆，以便我可以检查和删除影响 AI 的信息。
52. 作为用户，我希望备份包含会话、练习、缺口、复习状态和 sidecar 校验信息，以便更换电脑或恢复故障。
53. 作为用户，我希望恢复前可以预览范围并保留本地回滚副本，以便恢复失败时不会破坏当前数据。
54. 作为用户，我希望 macOS 提供双击启动的 Electron 应用，以便不需要手工启动 Python 或 Web 服务。
55. 作为用户，我希望同一套 Web UI 也能在本地浏览器运行，以便调试和后续扩展 Windows、Linux。
56. 作为中文用户，我希望所有可见界面默认使用简体中文，以便首版直接可用。
57. 作为用户，我希望产品只在本地文件发生变化时更新索引和学习记录，而不静默覆盖我的内容，以便长期信任这个工具。

## Implementation Decisions

- 首版采用单一 Web UI 与本地后端；Electron 只负责窗口、运行时监管、关闭和打包，不复制业务界面。
- 技术基线为 Next.js/React、Python FastAPI、SQLite、文件系统、Electron 和 BlockNote，进入实现前通过技术 spike 验证。
- 产品只借鉴并选择性复用 DeepTutor 的 Turn 运行时、解析、检索和 Electron 运行时监管经验，不 Fork 完整产品导航、25 模块系统、Partners、Memory 或插件生态。
- 一级信息架构为 Workspace、Review、Settings，`Cmd+K` 全局搜索是浮层。
- Workspace 主界面采用资料树、Markdown/PDF、AI 私教三栏结构；PDF 使用沉浸阅读模式。
- 可注册多个 Notebook workspace，但同一时间只激活一个；workspace 是索引、隐私和学习状态的隔离边界。
- 本地目录直接表示章节，Markdown 文件直接表示页面；不另存 `parent_id` 页面层级。
- Markdown 是主数据，BlockNote 的块 ID、自定义属性和布局保存到同名 `.md.note.json`。
- 外部 Markdown 修改后重新解析；应用内存在未保存内容时必须展示冲突，任何情况下不得静默覆盖。
- 笔记 tags 同时读取 YAML frontmatter `tags` 和正文 `#tag`；新建标签默认写 frontmatter。
- 模板位于可配置的 `.templates/` 目录；每日笔记默认位于 `Daily/YYYY-MM-DD.md`。
- 页面链接同时读取标准 Markdown 相对链接和 `[[Wiki Link]]`；新建链接写标准相对路径。
- 首版只支持 Markdown、纯文本和带文本层 PDF；不支持 DOCX、PPTX、扫描 PDF 或 OCR。
- PDF 使用内置只读查看器，支持翻页、缩放、文本选择、页码和选中文本引用。
- 所有 Learning session 必须绑定至少一个 Learning source；允许以后显式固定更多来源，引用可以跨资料。
- AI 输出分为 `grounded`、`insufficient_evidence` 和 `unsupported_supplement`；无效引用必须重试或降级。
- 默认使用引导式辅导，用户可显式要求直接解释；资料不足时不能输出未标记结论。
- 每个回答提供上下文抽屉，展示选中资料、自动检索片段和实际发送范围。
- AI 不建立隐藏自主记忆；个性化只读取当前会话、Gap record、Practice item、Review item 和设置。
- 本地索引覆盖标题、目录、正文、标签和 PDF 文本；全文检索是基础能力，向量索引是可降级增强。
- embedding 不可用或未配置时自动退回全文检索，两种模式使用一致的 Source citation 契约。
- 笔记图片以公开读七牛桶为唯一持久化存储，对象键包含 workspace 哈希和随机 UUID。
- 图片由本地后端上传，七牛密钥只从系统 Keychain 读取；浏览器不接触长期密钥。
- 图片上传成功后插入普通 HTTPS Markdown 引用；应用私有目录只保存可清理缓存。
- 已有本地相对图片原样保留，只有用户显式迁移时才上传并改写链接。
- 从笔记移图时询问是否删除七牛对象；删除页面默认不自动删除云端图片。
- Practice item 支持单选题和短答题；默认从当前学习上下文生成 3 题，可配置为 1 至 10 题。
- 短答题反馈包含参考要点、评分依据、命中项、遗漏项、Source citation 和用户可修正自评。
- 未掌握内容形成显式 Gap record；Review item 使用 1、3、7、14 天简单间隔，“重来”重置为 1 天。
- 使用 OpenAI-compatible 在线聊天服务和可选 embedding；首版不做本地模型和多供应商路由。
- 本地 SQLite 保存 workspaces、indexed sources、sessions、messages、citations、practice items、attempts、gaps、review items 和 index jobs。
- 学习记录全部带 `workspace_id`；删除会话不得级联删除源文件、Gap record、Practice item 或 Review item。
- 备份包包含设置、会话、练习、缺口、复习状态和 sidecar 校验信息；恢复前创建回滚副本。
- 首版 UI 默认为简体中文，但文案与结构保留国际化能力。
- 首版交付顺序为本地 Web 与 macOS Electron，之后补 Linux/Windows 打包。

## Testing Decisions

- 只使用一个产品级黑盒 seam：启动完整本地应用，连接临时 Notebook workspace，模拟模型与七牛服务，通过浏览器 UI 执行用户行为，并在操作后检查真实文件系统和本地数据库。
- 不把索引器、文件监听器、AI 编排器、练习生成器或复习调度器分别变成产品级测试 seam；这些模块可以有实现级单元测试，但验收必须通过同一个黑盒 seam。
- 好测试只验证外部可观察行为，不依赖内部类名、函数调用次数、数据库表实现或组件拆分。
- 首次启动测试：配置临时 workspace 和 mock 模型，跳过七牛，完成一次 Markdown 阅读和提问。
- 文件系统测试：在应用外创建、修改、移动和删除 Markdown，验证资料树、索引和引用状态。
- 冲突测试：在应用内有未保存编辑时外部修改同一个 `.md`，验证不会静默覆盖并保留恢复路径。
- sidecar 测试：保存 BlockNote 内容、从外部修改 `.md`、重新打开页面，验证 Markdown 内容与可恢复块结构。
- 图片测试：用 mock 七牛验证上传成功、上传失败、URL 写入、删除确认、离线缓存和旧图片兼容。
- AI 契约测试：验证 grounded citation、无效引用降级、资料不足和非资料补充三种输出。
- 多来源测试：固定多个 Markdown/PDF 来源，验证回答引用可以跨来源且能跳转到正确位置。
- 练习测试：生成单选与短答题，完成作答、反馈、自评修正、Gap record 和 Review item 创建。
- 复习测试：覆盖 1、3、7、14 天推进、“重来”重置、手动调整日期和单批 20 项上限。
- 搜索测试：通过 `Cmd+K` 搜索标题、正文、标签、会话、缺口和练习，验证精确跳转。
- 降级测试：关闭 embedding 后验证全文检索与引用格式仍可用。
- 备份测试：导出、清空临时环境、恢复并验证会话、练习、缺口、复习和 sidecar 关系。
- UI 测试：在 1280×800 和 1600×1000 视口检查中文文案、无重叠和关键操作可访问。
- 用户验收：5 位目标用户各自完成至少 3 次“提问 → 引用检查 → 练习 → 缺口 → 复习”闭环，至少 60% 的练习被认为有效，且无资料或学习记录丢失。

## Out of Scope

- 通用空白聊天、联网研究、深搜报告、子代理与实时外部智能体。
- 活书、课程生成、Mastery Path、完整掌握度图谱和自动学习路径。
- Partners、IM 渠道、账号、多用户、权限、协作与云端同步。
- 日历、任务板、技能市场、MCP、CLI 应用、第三方插件和远程技能。
- 自主长期记忆、Memory Graph、模型自动读取全部笔记或隐藏用户画像。
- 音频概览、视频课程、Manim、复杂可视化编辑器。
- DOCX、PPTX、扫描 PDF、OCR、音视频和普通文件附件。
- 本地模型、多供应商路由与模型目录。
- 托管 SaaS、自动更新服务器和遥测平台。
