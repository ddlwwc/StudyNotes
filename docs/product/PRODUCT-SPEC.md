# StudyNotes 产品规格

状态：已确认  
版本：MVP 1.0  
确认日期：2026-11-09
已发布：[Issue #1](https://github.com/ddlwwc/StudyNotes/issues/1)

## 1. 产品定义

StudyNotes 是一款本地优先、资料有据的个人 AI 私教。用户在本地 Markdown 与 PDF 空间中学习，通过可追溯的 AI 辅导、主动练习、知识缺口和复习形成完整学习闭环。

首版面向拥有自有资料、希望真正理解而不是只获得答案的个体自学者。产品不要求账号，不在首版提供云同步或多人协作。

### 1.1 核心价值

1. 学习内容与用户原有文件和编辑器工作流兼容。
2. AI 回答必须能够追溯到具体资料位置，资料不足时不伪装成有据结论。
3. 对话、练习、知识缺口和复习记录组成可长期使用的学习证据。
4. 用户在本地掌握资料、索引、会话和学习记录；联网模型与七牛图片的上传边界对用户可见。

### 1.2 首版不做

- 通用空白聊天、联网研究、深搜报告和子代理。
- 活书、课程生成、Mastery Path、完整概念图和学习路径。
- Partners、IM 渠道、多用户、账号、协作与云端同步。
- 日历、任务板、技能市场、MCP/CLI 扩展和第三方插件系统。
- 自主长期记忆、Memory Graph 或模型自动读取全部笔记。
- 音频概览、视频课程、Manim、复杂可视化编辑器。
- DOCX、PPTX、扫描 PDF 与 OCR。
- 本地模型和多供应商模型路由。

## 2. 用户与核心任务

### 2.1 目标用户

- 拥有 Markdown、PDF、课程讲义或个人笔记。
- 使用 Finder、Obsidian、Git 或其他编辑器维护资料。
- 希望围绕具体资料提问、练习和复习。
- 接受模型推理联网，但希望学习数据保存在本机。

### 2.2 核心任务

1. 连接已有本地资料目录，而不是重新导入一套副本。
2. 阅读 Markdown 或 PDF，并从当前页面、段落或选区发起提问。
3. 获得带资料引用、可核验、资料不足时会明确说明的辅导。
4. 把理解转化为单选题或短答题练习。
5. 把错误、未掌握内容和资料位置保存为知识缺口。
6. 按复习队列重新作答并更新下一次复习时间。
7. 在同一工作区中用 Markdown 记录、整理并再次引用学习内容。

## 3. 产品原则

1. 文件优先：Markdown 文件是用户可读、可编辑、可迁移的事实来源。
2. 资料有据：有据回答与模型补充必须视觉和语义区分。
3. 显式记录：个性化只来自用户可见、可删除的学习记录。
4. 本地隔离：索引、会话、练习和复习按 Notebook workspace 隔离。
5. 不静默覆盖：外部编辑器修改、上传失败和索引冲突不得破坏用户文件。
6. 单一职责：笔记、练习、知识缺口和复习各自保存，不通过嵌入内容制造重复状态。

## 4. 信息架构

### 4.1 一级入口

- **Workspace**：资料树、Markdown 编辑、PDF 阅读、AI 私教和块级讨论。
- **Review**：今日复习、知识缺口、继续学习和本周目标。
- **Settings**：模型、七牛、工作区、备份、语言与数据边界。
- **全局搜索**：通过 `Cmd+K` 打开的浮层，不占一级导航。

### 4.2 主工作区

桌面主工作区采用资料与笔记优先的三栏结构：

1. 左侧：当前 Notebook workspace、目录树、最近页面、每日笔记和标签。
2. 中间：Markdown BlockNote 编辑器或只读 PDF 阅读器。
3. 右侧：与当前位置绑定的 AI 私教、块级讨论、上下文抽屉和练习入口。

PDF 阅读进入沉浸模式：左侧页面与大纲，中间 PDF，右侧选区提问与引用。

Review 使用独立信息层级：到期复习、知识缺口、最近学习页面和本周完成度。

## 5. 核心流程

### 5.1 首次启动

1. 选择本地 Notebook workspace。
2. 配置 OpenAI-compatible 模型：Base URL、API Key、聊天模型。
3. 可选配置七牛公开读桶、访问域名、Access Key 和 Secret Key。
4. 完成连接测试并进入当前工作区。

七牛未配置时，阅读、编辑、辅导、练习和复习必须继续可用；图片上传入口显示未配置状态。

### 5.2 资料学习与辅导

1. 用户打开 Markdown 页面或 PDF。
2. 用户在当前段落、选区或页面发起提问。
3. 系统创建绑定当前来源与位置的 Learning session。
4. 系统组装显式选择、固定来源和检索命中片段。
5. 模型返回 Grounded answer、资料不足说明或经用户请求的 Unsupported supplement。
6. 回答显示 Source citation；上下文抽屉可查看实际发送范围。
7. 会话结束时可建议生成 Practice item。

### 5.3 练习

1. 用户点击“考考我”或在会话结束时接受生成建议。
2. 系统默认生成 3 道 Practice item，支持 1 至 10 道。
3. 单选题给出一个正确答案；短答题允许用户自由输入。
4. 系统依据资料生成评分依据，展示命中点、遗漏点和引用。
5. 用户可修正自评；最终结果进入 Practice attempt。
6. 未掌握内容可转为 Gap record。

### 5.4 复习

1. Review 页面显示今日到期项。
2. 用户逐项回答。
3. 系统展示参考答案、资料依据和上次反馈。
4. 用户选择“重来”或“通过”。
5. “重来”将间隔重置为 1 天；“通过”按 1、3、7、14 天推进。
6. 完成后从今日队列移除并写入下一次复习时间。

### 5.5 Markdown 写入和外部修改

1. BlockNote 编辑结果序列化为 `.md`。
2. 无法由 Markdown 自洽表达的块 ID、自定义属性和布局写入同名 `.md.note.json`。
3. 外部编辑器修改 `.md` 后，文件监听器重新解析内容。
4. 若应用内没有未保存内容，刷新编辑器并更新索引。
5. 若应用内存在未保存内容，展示冲突，禁止静默覆盖。

## 7. AI 输出契约

模型可以返回三种结果类型：

1. `grounded`：每个关键结论带至少一个有效 Source citation。
2. `insufficient_evidence`：说明当前资料无法支持结论，列出缺失信息。
3. `unsupported_supplement`：用户明确请求后的模型常识，必须单独标记。

系统在展示前验证：

- 引用指向当前 workspace 中存在的文件。
- 引用位置能解析到标题、块或 PDF 页码。
- 引用片段与实际发送给模型的上下文一致。
- 无证据的 `grounded` 回答降级为 `insufficient_evidence`。

默认回答语言为简体中文。用户要求直接解释时，仍先完成资料引用，再进入解释。

## 8. 数据模型

### 8.1 文件模型

```text
<workspace>/
├── 课程与论文/
│   ├── 注意力机制如何塑造工作记忆.md
│   └── 注意力机制如何塑造工作记忆.md.note.json
├── 研究论文/
│   └── 注意力与工作记忆_2024.pdf
├── .templates/
│   ├── 概念笔记.md
│   └── 论文阅读.md
└── Daily/
    └── 2026-11-09.md
```

图片不在 workspace 保存副本。Markdown 使用普通 HTTPS 图片链接。

### 8.2 本地应用数据

```text
<app-data>/
├── app.sqlite3
├── indexes/
│   └── <workspace-id>/
├── media-cache/
├── backups/
└── logs/
```

SQLite 至少包含：

- `workspaces`
- `indexed_sources`
- `index_jobs`
- `learning_sessions`
- `session_messages`
- `source_citations`
- `practice_items`
- `practice_attempts`
- `gap_records`
- `review_items`

所有学习记录带 `workspace_id`。删除会话不得级联删除源文件、Gap record、Practice item 或 Review item；用户显式删除学习记录时才删除对应关系。

## 9. 失败与恢复

| 场景 | 预期行为 |
| --- | --- |
| 模型不可用 | 保留草稿和会话，不丢失已输入内容，提供重试 |
| 七牛上传失败 | 不写入 Markdown，保留页面编辑状态并允许重试 |
| 文件被外部修改 | 无未保存内容时自动刷新；有修改时显示冲突 |
| 目录被移动 | 标记路径失效，要求重新定位，不删除学习记录 |
| embedding 不可用 | 自动回退全文检索并提示当前模式 |
| 索引失败 | 页面仍可编辑；显示失败文件和重建入口 |
| sidecar 损坏 | 从 Markdown 重建基础块，并保留损坏 sidecar 备份 |
| 备份中断 | 不覆盖现有数据；恢复前创建回滚副本 |

## 10. 非功能要求

- 本地文件操作不得阻塞编辑器输入。
- 索引、上传和模型流式回答必须显示真实状态，不使用无法解释的假进度。
- 密钥不得进入浏览器、日志、Markdown、sidecar 或 Git。
- 用户取消模型请求后，本地后端必须停止继续消费响应。
- 所有写文件操作使用原子写入或等价安全策略。
- UI 在 1280×800 及以上桌面窗口下无文字重叠或关键操作遮挡。

## 11. MVP 验收

### 11.1 用户验收

找 5 位目标用户，每人跨 Markdown 与 PDF 完成至少 3 次完整闭环：

1. 打开资料并提问。
2. 检查 Source citation。
3. 生成并完成 Practice item。
4. 形成 Gap record。
5. 在 Review 页面完成一次后续复习。

通过条件：

- 至少 60% 的 Practice item 被用户认为对理解有帮助。
- 无用户资料、笔记、会话或复习记录丢失。
- 用户能解释有据回答与模型补充的差异。
- 用户能通过上下文抽屉确认模型看到了哪些资料。

### 11.2 工程门禁

- BlockNote、Markdown、sidecar 往返测试无静默内容丢失。
- 外部编辑器并发修改测试通过。
- 删除索引或缓存后可完整重建。
- 备份恢复后会话、练习、复习和 sidecar 关系保持有效。
- macOS 桌面可从零启动本地后端与 Web UI。

## 12. 技术基线

以下为实现基线，需在 M0 技术验证中确认：

- Web UI：Next.js + React。
- Markdown 编辑：BlockNote。
- 本地后端：Python FastAPI。
- 本地存储：SQLite + 文件系统。
- 桌面壳：Electron。
- PDF：本地文本提取与前端 PDF 阅读器。
- 检索：本地全文索引 + 可选向量索引。
- 模型：OpenAI-compatible 流式聊天与可选 embedding。
- 图片：七牛公开读桶。

选择该基线是为了选择性复用 DeepTutor 的 Turn 运行时、解析、检索和 Electron 运行时监管经验，但不复用其完整导航、模块市场、Partners、Memory 或 25 模块产品结构。
